# Bugs

Every bug reported for Herb's Terminal, oldest first. New reports are added at the end and nothing is removed.
A box is ticked once the fix has shipped. A bug that affects several platforms has a box for each, and its main box is ticked when they're all done.
Items marked *found in testing* were found while testing other work, not reported by a user.

- [ ] **SSH stays connected after the remote host restarts or is switched off.** The session should end soon after the host goes away. *Reported 2026-11-07.*
  - [x] Mac: ends within about 15 seconds (keepalive every 5 s, gives up after 2 misses). Fixed in 1.0.11.
  - [x] Linux: same shared code. Fixed in 1.0.25.
  - [ ] Windows: same options for `ssh.exe`, in #5. Built and tested on Windows 2026-11-07 (a server that stopped answering ended the session with "Timeout, server not responding"); not yet merged.
- [x] **Linux: the app closed right after it opened.** Newer Flatpak already hands the shell its terminal, and taking it a second time failed, so the shell ended at once. *Found in testing, 2026-11-07.* Fixed in 1.0.25.
- [x] **Linux: the app called itself version 1.0.0.** The Flatpak build can't see git history, so the version was never worked out. *Found in testing, 2026-11-07.* Fixed in 1.0.25.
- [x] **Linux: building the Flatpak failed in a fresh VM.** *Found in testing, 2026-11-07.* Fixed in 1.0.25.
- [x] **Linux: Take Screenshot came back empty.** Snapshotting the window directly gave no picture on some calls. *Found in testing, 2026-11-07.* Fixed in 1.0.25.
- [x] **Linux: programs couldn't name their terminal.** `tty` failed and `GPG_TTY` broke, because terminals were created inside the sandbox. *Found in testing, 2026-11-07.* Fixed in 1.0.35 (#7).
- [x] **Linux: login scripts ran twice in every tab on Fedora-based systems**, so welcome messages showed twice. *Found in testing, 2026-11-07.* Fixed in 1.0.35 (#7).
- [x] **Linux: Take Screenshot drew see-through bars wrong.** The explorer's location bar and the MultiExec bar came out blank or unreadable. *Found in testing, 2026-11-07.* Fixed in 1.0.35 (#7).
- [x] **Linux: MultiExec and the Administrator mode lock didn't tell screen readers whether they were on.** They're now real toggle buttons. *Found in testing, 2026-11-07.* Fixed in 1.0.35 (#7). Not yet confirmed with a screen reader.
- [x] **Linux: two icons were missing** (the Settings Text tab, and the success mark in Run Command on Hosts). *Found in testing, 2026-11-07.* Fixed in 1.0.35 (#7).
- [x] **Mac: two layout tests failed on a busy machine.** They allowed a new tab's shell only 250 ms to start. *Found in testing, 2026-11-07.* Fixed in #7.
- [x] **The title kept the remote `user@host` after the remote host ended the SSH connection.** It should show this computer's `user@host` again. *Reported 2026-11-07 · Mac, Linux.* Fixed in 1.0.35 (#8). On Windows a dropped SSH tab stays that host's tab, so its title is already right.
- [ ] **The gap between Search and Tailcat Peers was wider than between the other toolbar buttons.** *Reported 2026-11-07.*
  - [x] Linux: fixed in 1.0.35 (#9).
  - [ ] Windows: in #5. Built and tested on Windows 2026-11-07 (the toolbar buttons are evenly spaced); not yet merged.
  - [x] Mac: already even; no change needed.
- [x] **Linux: Connect via SSH doesn't work.** Saved logins can't be managed or saved, and connecting to a host fails. Works on the Mac. *Reported 2026-11-07 · Linux.* Fixes in #12: the dialog's buttons, a crash when opening Manage Logins, ssh hanging at a new host's fingerprint question, and a crash when unlocking saved logins. Confirmed working on Aurora (1.0.40); ticked once released. Shipped in 1.0.73.
- [ ] **Mac tests: one test can hang the test run.** `hostCommandOutputIsCappedWhileItRuns` pipes `yes` into `head`; when broken pipes are being ignored, macOS's `yes` never stops. *Found in testing, 2026-11-07.*
- [x] **Linux: after typing `exit` in an SSH session, the app still shows the tab as connected.** *Reported 2026-11-07 · Linux.* Fix in #12 (the connection monitor waited forever on a finished ssh); confirmed on Aurora (1.0.40), ticked once released. Shipped in 1.0.73.
- [ ] **Linux: other short commands may wait out their time limit.** `Host.run`, the sudo checks and similar commands wait with Foundation's `Process`, which in the Linux app can miss that a command has finished; they would fail after their timeout (up to 20 s) instead of hanging. *Found in testing, 2026-11-07.*
- [x] **Tailcat: the app crashes and closes the moment Start Sharing is clicked.** *Reported 2026-11-07 · Linux.* Fix in #13 (a removed widget kept the keyboard focus); not yet retested. Shipped in 1.0.73; not yet retested.
- [x] **Tailcat: accepting a pairing asks to unlock saved logins with the Administrator Password, but the Tailcat Peers window offers no way to do that.** Unlocking in Connect via SSH and coming back works, but isn't practical. *Reported 2026-11-07.* Fixed by the new Lock / Unlock button (#13); not yet retested. Shipped in 1.0.73: the window's Unlock… button.
- [ ] **Linux: connecting through Tailcat fails** with "Connection closed by UNKNOWN port 65535" (Mac to Linux pairing). *Reported 2026-11-07 · Linux.* The Mac had the same bug. Fix in #13 (the proxy command began with variable assignments, which `exec` can't run); still failing on 1.0.45 (ping worked). Found 2026-11-07: the Linux side now works end to end (tested on Aurora against a Tailcat share); the Mac it connected to was sharing with Remote Login turned off, so nothing answered on port 22 and Tailcat closed the connection. #13 now makes Start Sharing check for SSH first and makes the connecting side say that nothing answered SSH on the peer (checked on Aurora with 1.0.46). Once Remote Login is on, needs a retest. 1.0.73 ships the fixes and the clearer messages; ticked once a connection succeeds with Remote Login on.
- [x] **Linux: dropping a file or folder from Dolphin on the terminal types nothing.** It should type the item's path, quoted, as on the Mac. *Reported 2026-11-07 · Linux.* Fix in the file-drop PR: drops are read from the file manager's plain list of file addresses (`text/uri-list`), which carries the real paths, instead of a GTK file list that can come back empty inside the Flatpak. The explorer's drop target has the same fix. The drop target also answers every hover with a copy: without that, Dolphin's drop never arrived. Tested on Aurora 2026-11-07: dropping files from Dolphin types their paths (quoted when they hold spaces or symbols, as on the Mac). Shipped in 1.0.73 (#14).
- [x] **Release builds: the x86_64 Flatpak fails in the Mac's container VM.** `script/build_flatpak.sh` stopped while building VTE for x86_64; the aarch64 build worked. The 1.0.73 x86_64 package was built natively on Linux instead. *Found in testing, 2026-11-07.* No VM any more: each Flatpak is built natively on a Linux machine of its architecture (#29).

- [ ] **Windows: screen readers can't see the toolbar, the tab strip or the window buttons.** They're drawn, not separate controls, so UI Automation found none of them (Narrator and the parity check alike). *Found while wiring up the parity check, 2026-11-08 · Windows.* Fix in the Windows parity PR: each drawn item is now a UI Automation control with the same identifier as on the Mac and Linux, its name, hover text and shortcut, and it can be pressed.

- [ ] **Windows: some toolbar names and hover texts differ from the Mac's.** Connect via SSH's hover text leaves out "the explorer follows that host"; Search is called "Search Terminal" (Mac: "Search"); the explorer switch is called "Show File Explorer" (Mac: "Switch Terminal / Explorer"). *Found in the parity check, 2026-11-08 · Windows.*
- [ ] **Linux and Windows: text at the same size is about a third bigger than on the Mac, so windows open bigger.** At 13 pt and 100 × 30, the parity scene's window is 826 × 519 points on the Mac, about 1010 × 714 on Linux and 1011 × 763 on Windows. The Mac draws a point as one screen point; Windows converts points to pixels at 72 per inch (`points × dpi / 72`, so 13 pt is about 17 px at 100 %), and GTK does the same through Pango. *Found in the parity check, 2026-11-08 · Linux, Windows.* Herbert chose to match the Mac (2026-11-08): the terminal font's points are now screen pixels before scaling (Pango `13px`, Windows `points × dpi / 96`), merged in #26 and #27, not yet released.

- [ ] **Linux: the self-test crashes when `HERBS_TEST_SSH` is set but empty or malformed.** The live SSH check splits the value without checking it and stops with "Index out of range" instead of skipping or reporting a failed check. `linux/dev/check.sh` now passes the variable only when it's set (#29); the check itself still needs the guard. *Found in testing, 2026-11-08 · Linux.*
- [ ] **Linux: the debug build has 31 compiler warnings, three of them errors in the Swift 6 language mode.** Main-actor-isolated statics are used from nonisolated code: `TransferQueue.shared` as a default argument in `RemoteExplorerModel.swift` and `defaultIterations` in the shared `CredentialStore.swift`. The rest: deprecated `utf8String` (CredentialStore) and VTE calls (`vte_terminal_get_window_title`, `vte_terminal_get_current_directory_uri`), and unused results. *Found in testing, 2026-11-08 · Linux.*
- [ ] **Linux: the Flatpak build fails when GitHub's release downloads are down.** On 2026-11-08 the tailcat archive returned 504 from github.com while the release and its API were fine; the build only went through after the archive was fetched with `gh release download` (checksum matching the manifest) into flatpak-builder's download cache. A mirror URL in the manifest, or a vendored copy, would keep builds working. *Found in testing, 2026-11-08 · Linux.*
